# 版本发布规则

用户要求每次更新都保留旧版本，适用于此项目的所有后续发布。

1. 修改版本号、CHANGELOG 和 README 版本差异，完成源码测试、视觉检查和独立 exe 验证。
2. 将更新提交到现有历史之后，不强制推送或重写历史。
3. 每个版本创建独立标签和 Release，例如 `v1.2.0`、`v1.3.0`。
4. 附件采用带版本号的 ASCII 文件名，例如 `Yuumi-v1.3.0-windows-x64.exe`，说明文字可使用中文。
5. 不删除旧 Release、旧标签或旧附件，不用新 exe 替换旧版本文件。
6. 发布前后核对旧版本的 Release ID、附件 ID、文件大小与 SHA256，确认旧版本完整保留。
7. 若新发布有问题，应创建修订版本；旧版本注明问题后继续保留。
8. 上传后核对新源码树和发布附件的 SHA256，再更新下载入口和验证记录。

开发环境、临时存档、原始聊天照片、缓存、构建中间目录和访问令牌不得提交到仓库。
